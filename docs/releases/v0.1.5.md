# v0.1.5

## What changed

MKE v0.1.5 publishes the existing local stdio MCP Agent-consumption contract. `search_library_v2`
reports bounded selection completeness (`complete`, `more_available`, or `capped`) and
`read_evidence_v1` reconstructs exact active Evidence with `evidence_text_sha256`. Equal-score FTS
and CJK ordering uses deterministic Source-byte-bound semantic keys with revision 2 cursors.

## Try it

Build from a source archive or checkout, then run the local stdio MCP server. The exact current
inventory is ten tools. GitHub Release distribution is source-only with zero assets; there is no
PyPI publication. Offline verification means prepared Python 3.12/3.13 interpreters and a
cache-warmed lock-derived environment.

```bash
uv build
uv run python scripts/release_consumer_smoke.py \
  --wheel dist/multimodal_knowledge_engine-0.1.5-py3-none-any.whl --json
```

## Upgrade from v0.1.4

Database, data, and schema migration: none. Valid legacy and v1 bounded calls remain compatible.
Exact `tools/list` consumers must update from eight tools to ten. Old cursors are not upgrade
authority; restart the initial call under the current process, policy, and active Publication.

## Verification

Release gates cover the installed wheel on Python 3.12 and 3.13, active Publication authority,
exact Evidence recovery, compatibility, and deterministic equal-score ordering. The already-merged
GitHub Actions pin update is maintenance only.

## Boundaries and non-claims

MKE does not claim relevance improvement, recall, precision, latency, or throughput.
Search is bounded and not exhaustive. Segmentation and contextual retrieval quality are not release
claims. Dense, RRF, and reranker remain comparison-only evidence with no runtime promotion.
MKE has no hosted service or deployment and does not claim production adoption or business impact.
OCR runtime, GraphRAG, an Agent loop, HTTP/SaaS, new providers, and uploaded assets remain excluded.
