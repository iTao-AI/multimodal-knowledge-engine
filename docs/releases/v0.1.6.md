# v0.1.6

## What changed

MKE v0.1.6 is a bounded patch release for atomic PDF intake publication. A successful
`PdfIntakeReport` is validated against the candidate Evidence page inventory and becomes visible
in the same SQLite transaction as the Publication, active search projection, Source pointer,
published Run transition, and event.

If a successful-candidate report insert fails, first publication and reprocess activation roll
back together; a prior active Publication remains unchanged and the validated Run remains retryable.
If a failed extraction report write fails, that Run is closed as `FAILED` while the public
application, CLI, and MCP error remains stable and redacted.

The existing local stdio MCP Agent-consumption contract remains the current ten-tool surface,
including bounded `search_library_v2` completeness and exact `read_evidence_v1` recovery.
Its `complete`, `more_available`, and `capped` states, `evidence_text_sha256`, deterministic
Source-byte-bound revision 2 ordering, legacy v1 compatibility, and ten tools remain unchanged.
Release verification requires a source archive or checkout and a GitHub Release with zero assets;
PyPI distribution is outside this release boundary. These are Stage 4 publication checks, not a
pre-publication state claim.

## Try it

Build from a source archive or checkout in a prepared cache-warmed environment:

```bash
UV_OFFLINE=1 uv build
UV_OFFLINE=1 uv run python scripts/release_consumer_smoke.py \
  --wheel dist/multimodal_knowledge_engine-0.1.6-py3-none-any.whl --json
```
