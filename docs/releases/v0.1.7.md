# v0.1.7

## What changed

MKE v0.1.7 is a bounded release-prep record for the eleven commits already merged after stable
v0.1.6. It records the current source checkout and does not assert a tag, GitHub Release, or
package publication.

The current source checkout includes:

- The native synthetic Evidence workspace projection and its provider-free documentation proof.
- MCP consumer failure-branch/recovery proof for normal no-match, capped non-exhaustive selection,
  and stale Evidence recovery (`evidence_not_found`) while preserving the aggregate v1 contract;
  the bounded next step is `search_current_active_evidence`.
- The `search_library_v2` CJK active-scan budget mapping: `cjk_scan_budget_exceeded` directs the
  Agent to `narrow_query_or_use_projection_strategy` and does not retry the unchanged query.
- The current checkout keeps supported dependency lines, the indirect `cryptography` lock update,
  the locked dependency set, lock-bound installed-wheel consumer proof, and the `setup-uv`
  v10.0.1 maintenance already recorded on the default branch.

## Contract and compatibility boundary

The exact ten-tool MCP v1 surface remains authoritative; the `ten tools` inventory is unchanged.
`search_library_v2` retains `complete`,
`more_available`, and `capped` selection states; `read_evidence_v1` reconstructs exact active
Evidence with `evidence_text_sha256`; equal-score ordering is deterministic. Source-byte-bound
revision 2 ordering and legacy v1 compatibility remain unchanged. Search and Ask read only the
active Publication.

The v0.1.6 atomic `PdfIntakeReport` publication boundary remains in force: successful reports and
Publication activation are committed together, while failed extraction report-write faults close
the Run as `FAILED` and leave the prior active Publication unchanged.

There is no schema migration and no dependency contract change. Dense, RRF, and reranker artifacts
remain comparison-only evidence with no runtime promotion. This record does not claim
retrieval-quality, performance, deployment, adoption, or business impact.

## Try it

Build from a source archive or checkout in a prepared cache-warmed environment:

```bash
UV_OFFLINE=1 uv build
UV_OFFLINE=1 uv run python scripts/release_consumer_smoke.py \
  --wheel dist/multimodal_knowledge_engine-0.1.7-py3-none-any.whl --json
```

The release verification surface links the product proof, demo, CLI, MCP, local knowledge proof,
retrieval evaluation, installed-wheel consumer, and source-pack checks. The proof inputs are
synthetic and provider-free; MKE does not claim production adoption or real external data.

Stage 4 publication verification is a separately authorized gate. It may verify the annotated tag,
the GitHub Release archive with zero assets, exact-main identity, and Git-free archive smoke after
those facts exist. PyPI distribution is outside this release boundary.
